A Station carries opaque bytes and nothing else

BadTower is LicoLand's Service Layer: one pure, protocol-neutral communication Station. Its native communication capability is the product.

What a Station is

A Station is one logical, independently operated BadTower Service Layer boundary. It is realized by one Station Instance or, after separate implementation and verification, by one Station Cluster. Clients and endpoints use it to move opaque Transport Units between opaque Station Addresses, under a small versioned contract.

Service Layer
The organizational layer owned by BadTower. It provides native, bounded communication-station behavior and infrastructure; external protocol meaning and endpoint trust remain outside it.
Station Core
The single BadTower runtime that directly implements the Native Station Contract, durable opaque transport, scheduling, pressure control, health, packaging, and one-member or multi-member Station behavior.
Native Station Contract
The versioned, protocol-neutral service contract for Reserve, Submit, Claim, Settle, health, capacity, and graceful shutdown. It is directly usable without a protocol plugin.
Station Instance
One independently startable, durable, recoverable, packaged, observable, and performant Station Core node, with no cluster coordinator and no required plugin.
Station Cluster
The deferred multi-node deployment of one logical Station: multiple replaceable Core members adding membership, placement, replication, consistency, fencing, failover, repair, rebalance, horizontal change, and disaster recovery.
Station Namespace
A bounded native caller scope for authorization, resource accounting, state, and observation. It carries no protocol identity or semantics.
Station Address
An opaque, bounded-lifetime destination token inside one Station Namespace — not an endpoint identity, agent address, or proof of ownership.
Transport Unit
Opaque bytes plus fixed native metadata for unit identity, destination, expiry, size, idempotency, and bounded carriage. The Core does not interpret the bytes.
Delivery Claim
A time- and count-bounded claim over eligible Transport Units, bound to a monotonic ownership epoch.
Settlement Record
The result of an idempotent native instruction to complete or release currently claimed Transport Units.
Station Signal
Any reservation result, admission result, claim, time, capacity state, settlement, health, or delivery statement produced by a Station. Its trust meaning belongs to the caller's own protocol and endpoint model.
Capacity Profile
A closed set of workload assumptions, hard limits, durability rules, failure model, latency, throughput, fairness, memory, storage, and recovery targets for one deployment shape.
Protocol Compatibility Plugin
An optional external process that implements one exact external protocol contract and maps it to the Native Station Contract. Absent by default.

Station Core owns the station, not the meaning

The Station Core owns its process lifecycle, configuration, liveness, readiness, graceful shutdown, and deterministic package; the Native Station Contract and direct native client behavior; the native entities listed above; bounded admission, authorization scope, storage, scheduling, fairness, idempotency, deduplication, expiry, retry, cleanup, and backpressure; hard ceilings for requests, bytes, connections, queues, workers, retained state, claims, retries, maintenance, and observation; privacy-minimal metrics and failure classes; and one-member durability, backup, restore, upgrade, rollback, and recovery. After standalone completion it also owns same-Station membership, replication, consistency, fencing, failover, repair, rebalance, and disaster recovery.

The Core's public and persistent schemas contain no agent, task, tool, resource, prompt, session, federation, external wire, protocol lifecycle, endpoint identity, or product-specific field.

Instance first, Cluster later

Delivery order is mandatory: complete the Station Core, then complete and verify one standalone Station Instance, then extend the same native contract into a Station Cluster. Only after native single-node and clustered excellence does an external extension contract arrive, and only then explicitly selected Protocol Compatibility Plugins. Later stages cannot repair or redefine unfinished native behavior.

What a Station deliberately is not

  • Not an endpoint trust layer or external protocol authority.
  • Not a container for LicoArc, A2A, ACP, or MCP — those are optional external plugin plans, never Core features.
  • Not a federation, agent network, or multi-station fleet; Cluster membership never defines external protocol topology.
  • Not an owner of endpoint keys, encryption, plaintext, identity proof, approval, replay decisions, or final endpoint evidence.
The current Go source implements a native Station Instance candidate and a partial Cluster consensus foundation; the Native Excellence Gate is not accepted. See Where BadTower stands.
