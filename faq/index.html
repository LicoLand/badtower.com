Questions a newcomer asks

Short answers, strictly from the repositories' own documentation. Where the two implementations differ, each answer says which one it describes.

Is there a hosted BadTower I can use?

No. No named hosted BadTower Station, Station Cluster, extension service, protocol plugin, or official network is claimed operating. Source availability and a successful local start do not establish hosted operation. Both repositories describe software you run yourself.

Can the Station operator read my messages?

The Station is designed so it cannot read payloads: the Go Core treats Transport Units as opaque bytes, and the BadTower.js Worker routes 32-byte delivery handles without seeing plaintext, identities, or sessions. That said, every deployment remains untrusted from an endpoint's perspective — endpoints keep keys, encryption, identity proof, and final evidence for themselves. Do not put trust into a Station Signal.

Why is it called “BadTower”?

The name states the posture: treat the Station as untrusted infrastructure. It carries opaque bytes, and a Station Signal never proves identity, receipt, or effect.

Do I need LicoArc to use a Station?

No. The Native Station Contract — Reserve, Submit, Claim, Settle, health, capacity, graceful shutdown — is directly usable with no protocol plugin. LicoArc, A2A, ACP, and MCP are optional external plugin plans, never Core features.

What is the difference between BadTower and BadTower.js?

Two repositories, two implementations of the Station idea. The Go repository builds the native Station service: one protocol-neutral Station Core, a Station Instance candidate, a Station Cluster candidate, and the external-plugin boundary — currently pre-release, with the Native Excellence Gate open. BadTower.js is a permanent-mailbox relay on Cloudflare Workers — one Worker plus one SQLite Durable Object per mailbox — currently in pre-1.0 preview.

What happens to undelivered units?

It depends on the implementation. In the Go contract, Transport Units are submitted under explicit expiry, and expired state is reclaimed incrementally while the service runs. In BadTower.js, undelivered packets never expire: a stored packet leaves only on the recipient's settle or on revocation.

Can a plugin change the Station Core?

No. The Core never discovers, loads, embeds, or supervises plugins. A plugin's absence, crash, overload, upgrade, rollback, or retirement cannot change the Core artifact, the native contract, the persisted schema, or another plugin — and a plugin requirement cannot widen the native contract unless the capability independently serves direct native clients and passes Core acceptance.

Can I treat a Station's answers as proof of delivery?

No. A Station Signal never proves peer identity, authenticity, integrity, freshness, replay rejection, user approval, endpoint receipt, task completion, tool effect, or business acknowledgement. Signals can guide service-local retry or operation; endpoints verify everything that matters in their own protocol.

How do clients talk to a Station?

Go Station: gRPC service badtower.station.v1.Station over TLS 1.3 with ALPN h2, or a mode-0600 Unix socket, with bearer credentials on every data-plane RPC. BadTower.js: HTTPS at /v1/native/* plus a licoarc.mailbox.v1 WebSocket listener, all under an offline-minted btm1 admission credential.

What licence covers the source?

Both repositories are AGPL-3.0-or-later.
